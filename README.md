## About The Project

Multi-modal **Magnetic Super-Resolution (MSR)**: deep-learning enhancement of
low-resolution aeromagnetic surveys, framed as a physics-constrained downward-continuation
inverse problem. The repo contains everything behind the accompanying report: two
reproducible dataset builds (WA Goldfields ×4, KSA Arabian Shield ×3), RDN++ and U-Net
trainers with auxiliary conditioning inputs (1VD, DEM) and an FVD spectral loss, a buffered
cell-grid 5-fold cross-validation protocol, a differentiable draped upward-continuation
operator, and full-region reconstruction with pixelwise uncertainty.

**Reproducing the report tables?** Build the datasets (below), then go straight to
[`experiments/ksa_ablations/README.md`](experiments/ksa_ablations/README.md) — train the
62-run sweep, score it into one CSV, render every table. Trained checkpoints are not
distributed; the sweep retrains them. [`experiments/README.md`](experiments/README.md)
indexes all trainers, evaluators, and figure scripts.

### Built With

* Python 3.13
* [uv](https://github.com/astral-sh/uv)
* PyTorch

<!-- GETTING STARTED -->
## Getting Started

### Prerequisites

Install `uv` (fast Python package manager):

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### Installation

1. Clone the repository
   ```bash
   git clone https://github.com/chipnbits/multi-modal-msr.git
   cd multi-modal-msr
   ```

2. Set up the environment and install dependencies

   PyTorch requires selecting a compute backend. Pick **one** of the following extras:

   ```bash
   # CPU-only (lightweight, no GPU support)
   uv sync --extra cpu

   # CUDA 12.8 (for NVIDIA GPUs with CUDA 12.8)
   uv sync --extra cu128

   # CUDA 13.0 (for NVIDIA GPUs with CUDA 13.0)
   uv sync --extra cu130
   ```

   > **Note:** The extras are mutually exclusive — only one can be installed at a time.
   > To switch backends, delete `.venv` and re-sync with the desired extra.

3. Install pre-commit hooks
   ```bash
   uv run pre-commit install
   ```

## Usage

Everything runs through `uv run` (scripts, `pytest`, `jupyter lab`); the environment lives
in `.venv/`, which editors can use as the Python interpreter. The typical workflow:

```bash
uv run pytest                                                  # sanity-check the install (no data needed)
# build a dataset (per-dataset instructions below), then e.g.:
uv run python experiments/ksa_ablations/train.py --all         # print the sweep's train commands
```

The three reusable pieces for other projects are the two dataset build
pipelines (`scripts/build_*_dataset/`, each with its own README), the

## Datasets

The package supports two main datasets for magnetic super-resolution:
- Western Australia aeromagnetic survey (Goldfields region, see [figures/wa_study_area_overview.png](figures/wa_study_area_overview.png))
- KSA Shield aeromagnetic survey (multiple blocks across Saudi Arabia)

The KSA Shield dataset is used in its pre-snapped form: every product mosaicked and co-registered onto a common EPSG:32637 grid (the "aligned" dataset, loaded by `magsr.datasets.ksa_shield_aligned`). The snapping itself is part of the scripted build below.

### File Location Paths

```bash
cp .env.example .env
# then edit .env and fill in the paths below for your machine
```

[`.env.example`](.env.example) is the reference for which variables exist and what directory layout each dataset root must contain. If a variable isn't listed there, it isn't read anywhere in the codebase.

### Western Australia

#### Aeromagnetic Survey

The Western Australia dataset is publicly available from the [Geological Survey of Western Australia](https://magix.dmirs.wa.gov.au/datasets/magnetic-anomaly-grids) with the downloads accessed as the 80m/20m TMI products and the 80m TMI_1VD from the [MAGIX download portal](https://geodownloads.dmp.wa.gov.au/downloads/geophysics/72204/).

> Brett, JW, 2026, 80m TMI, 1VD and 20m TMI magnetic merged grid of Western Australia. Geological Survey of Western Australia. Available from: https://magix.dmirs.wa.gov.au/datasets/magnetic-anomaly-grids [Accessed 2026-06-01].

The downloaded grids are for a much larger area than the Goldfields region and can be trimmed down to the smaller Goldfields window. The following preprocessing steps reproduce the WA Goldfields dataset used in the experiments and code of this repository.

1. From the portal download the `WA_Magnetics_80m` products:
   - Total_Magnetic_Intensity_(TMI)_grid.zip
   - First_vertical_derivative_(1VD)_of_TMI_grid.zip

2. From the portal download the `WA_Magnetics_20m` products:
   - WA_20m_Mag_Merge_v1_2023_7z.bin

3. Extract the archives into the repository folder `data/WA/raw/`. The expected layout:

```
data/WA/raw/
├── 20m_mag/
│   ├── WA_20m_Mag_Merge_v1_2023          # ~31 GB binary  (HR TMI source)
│   ├── WA_20m_Mag_Merge_v1_2023.ers      #
│   └── WA_20m_Mag_Merge_v1_2023.ers.aux.xml
└── 80m_mag/
   ├── WA_80m_Mag_Merge_v1_2023(.ers)        # ~2 GB  (LR TMI source)
   └── WA_80m_Mag_Merge_1VD_v1_2023(.ers)    # ~2 GB  (LR 1VD source)
```

4. Run the build scripts in order to reproduce the Goldfields dataset. Each is self-documented and reads its defaults from `configs/datasets.yaml`, following the work of ([Smith et al., 2022](https://doi.org/10.1016/j.oregeorev.2022.105119)) for the `128×128` patch tiling:

```bash
# Clip the state-wide grids to the Goldfields window: HR (TMI) + 2-band LR [TMI, 1VD].
# (Also verifies CRS and the 4× HR/LR cell ratio.)
uv run python scripts/build_wa_dataset/01_clip_wa_goldfields.py

# Render the study-area overview (figures/wa_study_area_overview.png)
uv run python scripts/build_wa_dataset/02_plot_wa_overview.py

# Snap the Geoscience Australia 1" SRTM DEM-S onto the LR grid (DEM-gradient channel).
uv run python scripts/build_wa_dataset/03_fetch_snap_wa_dem.py

# Build normalized HR/LR .npy patch pairs into data/processed/wa/patches/ (see --help for channel flags).
uv run python scripts/build_wa_dataset/04_patch_wa_dataset.py --lr-aux 1VD --use-dem
```

### KSA Shield aeromagnetic survey

The KSA data is derived from the [National Geological Database Portal](https://ngp.sgs.gov.sa/) (SGS). The whole chain — portal tiles → one co-registered grid → patch indices — is scripted in [`scripts/build_ksa_dataset/`](scripts/build_ksa_dataset/); only the download itself is manual, because the portal is an authenticated map application that emails a link rather than serving a bulk API.

#### 1. Acquire the raw tiles

Register at the portal and request, over your AOI, the HR survey blocks and the legacy LR compilation, choosing the derivative products you need (AMF, RTP, RTP1VD, ANS, DTM, …). [`00_ksa_preprocessing/README_ksa_data.md`](scripts/build_ksa_dataset/00_ksa_preprocessing/README_ksa_data.md) walks the portal flow layer by layer and lists the products this project uses.

#### 2. Sort and snap onto one grid

[`00_ksa_preprocessing/`](scripts/build_ksa_dataset/00_ksa_preprocessing/) turns that download into the co-registered tree the dataset class reads — HR 60 m, LR 180 m, DEM 30 m, all on EPSG:32637 with integer pixel ratios (1 LR px = 3×3 HR = 6×6 DEM):

```bash
# Sort incoming tiles into per-block folders + print a CRS / pixel-size / band inventory.
uv run python scripts/build_ksa_dataset/00_ksa_preprocessing/01_organize_raw_downloads.py \
    --incoming data/raw/ksa_shield/_incoming --output data/raw/ksa_shield

# Mosaic + reproject + clip each product onto the master grid (one config per product).
# The master grids ship with the repo, in data/ksa_base_grids/ — nothing to build first.
uv run python scripts/build_ksa_dataset/00_ksa_preprocessing/03_snap_raster.py
```

Steps 02 and 03 are config-driven: each reads a YAML from [`00_ksa_preprocessing/config/`](scripts/build_ksa_dataset/00_ksa_preprocessing/config/) (override with `--config`), with paths inside resolved against the repo root. Ship one config per grid and per snapped product; the sub-README documents both schemas.


#### 3. Point the env var at the result

| Env var | What it points at | Used by |
|---|---|---|
| `MAGSR_KSA_ALIGNED_ROOT` | The snapped single-grid tree from step 2 (or a snapshot of it shared between collaborators, which skips steps 1–2) | `magsr.datasets.ksa_shield_aligned` |

Condensed layout:

```
$MAGSR_KSA_ALIGNED_ROOT/
├── 00_base_grid/
│   └── magnetic_mask_grid60m.tif                                  # uint8 block-ID raster (0=nodata, 1/2/3=blocks)
├── 02_snap_owned/
│   ├── aeromagnetics/
│   │   ├── 60m/cubicspline/snapped_cubicspline_MAG_{product}.tif  # HR products (e.g. AMF_RTP)
│   │   └── 180m/cubicspline/snapped_cubicspline_{stem}.tif        # LR products (RTP, TMI, ...)
│   └── elevation/snapped_cubicspline_dem30m.tif                   # 30 m DEM
└── 03_inference_lr/cubicspline/                                   # LR on the extended inference grid
```

See [`.env.example`](.env.example) for the full tree.

#### 4. Build the patch indices

Scripts `01`–`06` in [`scripts/build_ksa_dataset/`](scripts/build_ksa_dataset/) take it from there: per-block histograms → block normalization → `normalization.json` → cell-grid indices → train/val/test (or K-fold) splits. See its [README](scripts/build_ksa_dataset/README.md) for the sequence and the CV variants.
